POWER BI IMPACT ANALYZER - VERSION HISTORY

Version 1.0 - First public release

Analysis
- Builds a dependency graph of the connected model and reports, for every table, column and measure, all objects affected by a change (direct and indirect), with level and shortest path.
- Dependency sources: measures, calculated columns, calculated tables (and the columns they generate) and sort-by-column links.
- Relationships are reported as notes on the columns that use them.
- Skips Power BI auto date/time tables (LocalDateTable_*, DateTableTemplate_*) and RowNumber columns. User-defined calculated tables are kept.
- Objects with no dependents are reported with impact 0 instead of being omitted.
- Full DFS paths are listed only for the objects selected in the model tree (or named in cfgDfsTargets), with a configurable path limit.
- Registry keys are built from object type, owner and name; key collisions, unknown object types and graph endpoint problems are reported in the log.

Output
- One folder per run: Desktop\ImpactAnalysis\Run_<timestamp>\
- ImpactReport_<model>.html: searchable report with an Explorer tab and a Paths & log tab.
- ImpactReport_<model>.csv: one row per (target, affected object) with level and shortest path.

Settings
- cfgDebug, cfgMaxPaths, cfgDfsTargets, cfgExportHtml, cfgExportCsv, cfgOpenFolder, cfgOutputRoot (see README).
- Synthetic self tests (key boundaries, cycles, path limit, BFS/DFS consistency) run only when cfgDebug = true and are written to the log tab.

Validation
- Tested on two Import-mode Power BI models and one model connected live to SSAS (connected directly through File > Open > From DB).
- Not covered by the analysis: report visuals and filters, RLS expressions, calculation items, KPIs, Power Query (M) lineage.
